# Rigwright roadmap

## Current scope

Rigwright currently implements seven proposal-only leaves for routing, atomic skill authoring, plugin-container authoring, evaluation, migration planning, lifecycle prioritization, and copy-only archiving. Claude Code and Codex adapters are generated only in explicit `candidate-sandbox` mode. An external lifecycle authority remains the lifecycle and priority owner.

## Before any public launch

- Preserve raw machine-local evidence privately and keep it excluded from deterministic public-package candidates.
- Complete owner human review of the frozen runtime evaluation and resolve critical-failure instances.
- Designate a public security-reporting channel.
- Confirm the canonical public host project and URL.
- Confirm the release policy for the owner-selected cross-surface `0.1.0` baseline.
- Independently qualify the exact committed launch candidate.

## Later, separately gated

- Evaluate a compatibility-preserving cutover from existing authoring tools.
- Bind accepted Rigwright records into the external lifecycle authority without creating a second lifecycle authority.
- Qualify install, enablement, discovery, rollback, and readback behavior per surface.
- Consider separate atomic leaves for MCP, agent, hook, command, and app authoring only after their security and evaluation contracts exist.

## Non-goals

- Silent installation, activation, promotion, or marketplace edits.
- Provider execution without a separate approval.
- Treating folder order as lifecycle or routing authority.
- Folding MCP, agent, hook, command, or app creation into the initial leaves.
- Deleting archives, raw evidence, or legacy skills as part of authoring.
